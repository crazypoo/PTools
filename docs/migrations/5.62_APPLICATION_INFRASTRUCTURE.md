# 5.62 Application Infrastructure Migration

## 产品边界

5.62 的 Database、Auth、Sync、Transfer、StoreKit、Observability、WebBridge、Map、AppIntegrity、Remote Configuration 和 Realtime 都是 opt-in 产品，不进入默认 `PooToolsAll` / Core 路径。

## 推荐迁移顺序

1. 先引入对应 product，并保持业务模型使用 Foundation `Sendable` 值类型。
2. Database 使用 `PTDatabaseMigration(fromVersion:toVersion:statements:)`，正式启用前执行 `validateMigrations` 和 `integrityCheck`。
3. Auth 使用 `PTAuthService`、`PTAuthState` 和 `PTAuthUnauthorizedReplayCoordinator`，旧 Network 入口只负责适配。
4. Transfer 使用 `PTTransferRequest`、优先级、重试策略和事件流；后台任务需要宿主提供稳定 identifier。
5. Sync 使用数据库 mutation store、游标 pull 和事件流；冲突策略由宿主明确选择。
6. WebBridge 使用 `PTWebSecurityPolicy`，显式配置 allowed origins/methods，不把页面输入当作可信数据。
7. Remote Configuration 使用 ETag / Last-Modified、签名 verifier 和 LKG fallback；kill switch 必须由宿主定义默认安全行为。
8. Realtime 选择 SSE 或现有 `PooToolsSocketKit` WebSocket，不同时维护第二套 transport。

## 兼容与限制

现有 Core 和公开旧入口不删除。真机、StoreKit 沙盒、App Attest 服务、后台 relaunch 和生产远程配置必须在宿主工程中验证。
