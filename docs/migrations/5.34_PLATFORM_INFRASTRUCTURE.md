# 5.34.0 平台基础设施迁移说明

5.34.0 不删除旧的 Network、Socket 或 Router API。新增能力是可选入口，旧代码可以继续使用 `PooTools/Core`。

## 推荐迁移顺序

1. 需要网络状态时引入 `PToolsConnectivity`，只依据快照调整 UI、重试或诊断，不在请求层硬编码离线失败。
2. 新增持久化数据时使用 `PToolsStorage`，为每个模块和功能创建独立 `PTStorageNamespace`。
3. 新增 URL Scheme、Universal Link 或通知跳转时，先生成 `PTRouteRequest`，再交给 `PooToolsRouter`。
4. 新增通知和后台任务时，使用类型化 payload/registration；不要把 token、Cookie、完整通知字典写入日志。

## 兼容规则

- SwiftPM 通过独立 product 导入；CocoaPods 通过对应 subspec 导入。
- UIKit 只出现在 Router 的展示适配层和系统 UI 服务中。
- `Any` 和 `[AnyHashable: Any]` 只允许停留在 Apple 系统回调边界，不作为公共并发模型。
- 5.x 继续保留旧入口；新的迁移提示和弃用处理在后续 API Freeze 阶段统一推进。
